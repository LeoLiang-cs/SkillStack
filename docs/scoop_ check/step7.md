# Step 7 — Articulate the Delta

- **Timestamp:** 2026-09-08T20:53:41-07:00

## Delta

> Unlike **AgentSquare**, which searches for high-performing combinations inside a predefined four-module uniform-I/O design space, **SkillStack preserves paper-native skill artifacts and performs fixed-neighbor cross-paper swaps plus matched pairwise factorials before defining a shared interface**, yielding measurable swap compatibility, adapter information loss, performance portability, and cross-module interaction rather than only a better-scoring agent.

## Verdict

**Level 2 — High Overlap.** AgentSquare already covers modular cross-system component reuse/recombination with standardized interfaces; MAFBench covers controlled architecture-level comparison; SkCC covers cross-framework skill portability through an IR; Harnessing Agent Skills covers a skill-specific reference architecture; SkillOps covers a drop-in skill-library component with method-conditional effects; Skill Runtime Intelligence covers executable adapter qualification and hidden evidence semantics; and Does Memory Credit Travel covers paired factorial attribution in ALFWorld. None combines all four SkillStack axes—paper-native multi-slot skill components, fixed-neighbor swaps, explicit semantic-loss accounting, and schema-later interface induction—but the delta rests on that exact combination. Broad “first modular/composable/reference architecture” language would not survive review.

## Recommended claim boundary

- Do not claim: first modular LLM-agent architecture; first composable skill system; first skill reference architecture; first skill portability/evaluation framework; first factorial study of external agent artifacts.
- Defensible claim: a **skill-specific, cross-paper component compatibility testbed** that preserves native representations, classifies compatibility separately from task performance, and derives candidate interface fields from observed adapter friction and cross-component failures.
- Evidence still needed before a strong paper claim: at least two genuinely different implementations in each declared slot; more than one cross-paper slot family; repeated matched runs with uncertainty; at least one second environment; and a demonstrated case where an empirically added interface field predicts or repairs a reproducible failure.
