# SkillStack Phase 2C/2D——第四次导师简报（中文版）

- **当前状态：** 执行器替换（2C）完成；更难区间实验（2D）完成。
- **一句话结论：** 三个发现——稳健的天花板、预算压力下的技能信号、以及已解决的 GLM 可移植性归因。

## 1. 本周回顾

- **2C：** 用零样本 LLM ReAct 执行器替换确定性执行器（零相邻改动）。DeepSeek 使 5 个冻结任务饱和（no-skill 5/5），G2 失败；GLM 在动作合法性上失败（F-15）。
- **2D：** 冻结 8 任务更难集（pick_two + 第二实例）、紧预算下测技能效用、跑 GLM few-shot 归因探针。

## 2. 发现

### 发现一：天花板是稳健的（不是任务选择假象）

8 任务更难集在 50 步下也被**无技能**全解（no-skill 8/8 = oracle 8/8）。`deepseek-v4-flash` 零样本 ReAct 对 ALFWorld `valid_unseen` 六个家族的文本任务整体饱和。这是"环境 + backbone 配对"的负结果，不是技能思路的负结果。

### 发现二：预算压力下技能上下文有用（首个正信号）

在 pick_two 家族上，oracle 用 **47 步**解完三任务，no-skill 用 **88 步**——接近 2 倍效率差，且发生在成功率触顶的情况下（no-skill 有一集用了 48/50 步）。

把预算卡到 20 步，效率差转化为成功率差：

| 条件 | 成功率（3 个 pick_two × 20 步） |
|---|---:|
| no_skill | **1/3** |
| random_skill | 2/3 |
| lexical | 2/3 |
| oracle | 2/3 |

no-skill 严格低于所有带技能条件——预算约束下技能通道可测地有帮助。

### 发现三：GLM 失败是 prompt 耦合，不是能力上限（归因已解决）

加两个 worked examples 后，GLM 的首发动作合法性率从零样本的"频繁失败"升到 **97.96%**。F-15 重分类：执行器**能**移植到 GLM，只要 prompt 带 few-shot 示例。GLM-4.7-FlashX 是这个执行器的可行廉价后端。

## 3. Gates

| Gate | 结果 |
|---|---|
| G1 格式（deepseek） | 通过（0 非法动作） |
| G1 格式（GLM 零样本） | 失败 → **2-shot 解决**（97.96% 合法） |
| G2 技能通道（5 任务 × 50 步） | 失败（天花板：5/5=5/5） |
| G4 技能通道（更难集 × 50 步） | 失败（天花板：8/8=8/8） |
| G4′ 技能通道（pick_two × 20 步） | 部分（no_skill 1/3 < 带技能 2/3，但 oracle 未胜 random） |

## 4. 现在可以主张的结论

1. 执行器槽位在结构上可互换，且含完整 token/成本核算（RQ2 边界）。
2. `deepseek-v4-flash` 零样本 ReAct 在 50 步下使 ALFWorld `valid_unseen` 饱和——跨两个任务集可复现的天花板发现。
3. 在预算约束下，技能上下文可测地有帮助（pick_two 上 no-skill 1/3 vs 带技能 2/3）。
4. 严格执行器配 2-shot prompt 可移植到 GLM（合法性 97.96%）；零样本失败是 prompt 耦合，不是能力上限。

## 5. 仍然不能主张的结论

1. "正确技能"比"任意技能文本"更重要：pick_two 上 oracle 未与 random 分离（都 2/3）。
2. 统计结论（n=3）。
3. 该区间之外的技能效用一般性结论。

## 6. 建议的下一步

判别区间已定位：**pick_two + 约束预算**。为把发现二升级为"特定技能"结果，按序：

1. **扩充 pick_two 实例**（3 → 9+），在 20 步预算下给 oracle-vs-random 比较提供统计功效。
2. **结构化技能注入**（D4）：注入编号 procedure 步骤而非平文本，让正确技能的内容更强制地塑造计划——第二周 F-06/F-07 的具体检验。
3. 把效率（步数/token）作为与成功率并列的主指标。

## 7. 希望与导师讨论的决策

1. 先扩 pick_two 实例重跑 4 条件紧预算，还是先在现有 3 任务上做 D4 结构化技能？
2. "预算下任意技能文本都有帮助"是否可作为阶段性发现，还是必须证明"正确技能特异性"才能推进？
3. 后端：继续 DeepSeek 为主，还是切到 GLM-4.7-FlashX（2-shot，已 97.96% 合法性、更便宜）？

## 8. 四页汇报结构

1. **替换 + 天花板**：执行器替换成功；deepseek 使 ALFWorld 饱和（8/8 no-skill）。
2. **技能信号**：pick_two 效率（47 vs 88 步）+ 20 步成功率分裂（1/3 vs 2/3）。
3. **可移植性解决**：GLM 2-shot → 97.96% 合法性 = prompt 耦合。
4. **决策**：扩 pick_two / 结构化技能 / 后端选择。

## 9. 口头汇报稿

"这一周我把执行器换成了 LLM ReAct，结果撞上一个硬天花板：DeepSeek 在无技能时也能解完 ALFWorld——原五个任务和八任务更难集，no-skill 都打到 8/8。所以 50 步下技能效用测不出来。

但更难的双物体任务给出了第一个真信号：oracle 技能 47 步解完，no-skill 要 88 步；把预算卡到 20 步后，no-skill 掉到 1/3，所有带技能条件都是 2/3。技能在预算约束下确实有用，只是还看不出'正确技能胜过随机技能'。

另外 GLM 的失败查明是 prompt 耦合、不是模型上限：加两个示例后它的动作合法性跳到 98%，所以 GLM 是这个执行器的可行廉价后端。

下一步我想把双物体任务扩到九个左右，重跑紧预算对比——那才是'特定技能'结果能出现的地方；同时并行测试把技能按编号步骤注入、而不是平文本。"
